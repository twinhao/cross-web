# 叫號與報到入口整理

使用者確認主要問題是畫面與操作入口重複。本次將現場動作集中，不增加新的業務狀態，也不改成報到先後排序。

| 畫面 | 主要工作 |
|---|---|
| 今日／預約管理 | 查詢、新增、改期、取消與完整紀錄；現場入口接續同一位客戶 |
| 叫號與報到 → 待報到 | 只列已確認預約，按「報到」移入候診 |
| 叫號與報到 → 候診與服務 | 每位人員區分服務中與候診中；先完成服務，再叫下一位 |

## 操作規則

- 以日期、階段與預約 ID 接續，姓名／電話不寫入網址；記憶體示範沿用 `/demo`。
- 點客戶姓名可回到同筆預約詳情，頁首「預約與紀錄」帶入同日查詢。
- 現場頁不混列完成、取消、未到。預約詳情不再重複現場完成按鈕；歷史／未開通叫號的情境保留「補登完成」。
- 待報到按預約時間排列；候診依原號碼先後，未報到者不進入候診。叫號成功即沿用 `in_progress`，介面明示為服務中。
- 新叫號請求帶 `require_idle=true` 及預期預約 ID；後端在原群組交易鎖內核對。舊版未帶參數者維持原行為，無資料庫遷移。
- 非今日在本介面僅查詢；後端原有日期政策不變。完成服務須核對客戶及時段後確認。
- 初次載入顯示骨架，背景更新保留名單。讀取失敗標示保留上次資料並禁止繼續操作；寫入成功後讀取失敗仍保留成功訊息。
- 切換日期與院所拒絕舊回應覆蓋；更新不重複捲動焦點，開啟完成確認時暫停自動刷新。
