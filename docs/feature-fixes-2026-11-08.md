# 功能合理性與櫃檯流程修正

依 2026-11-08 功能介紹檢查修正日常操作與對外說法。

## 日常操作

- 新增 `facility_receptionist`（櫃檯人員），可處理同院所的代訂、改期、取消、完成、未到、報到及叫號。設定、客戶檔案、訂閱、試用及帳號寫入仍限原有管理員。
- 現有 `facility_staff` 保持唯讀。平台管理員可於既有帳號管理指派櫃檯角色及院所；本次不自動變更任何帳號。
- 已選取的既有客戶以 `patient_id` 建立預約，不再要求輸入完整證號。畫面保留姓名、電話與證號末四碼供核對；「更換客戶」回到新客必填資料。
- 後端核對操作權限、院所與啟用狀態，拒絕跨院所／停用客戶及混合識別欄位；原有新客格式仍相容。時段衝突及方案檢查保留。
- 示範同步沿用既有客戶紀錄；一般代訂可不指定服務，新客建立獨立示範紀錄，不借用其他客戶身分。示範仍使用分頁記憶體，禁止回退正式 API。

## 名稱與介紹

- 提醒明確稱為「App 預約提醒」，說明有效方案、會員對象綁定及裝置通知條件。Web 可預約；不因預約成功而承諾 Email、簡訊或瀏覽器通知，電話／現場代訂不保證取得 App 提醒。
- 公開方案改稱「未到統計與回訪分析」，訂閱可用功能不再列出尚無 Web 操作入口的未到風險。後端既有 entitlement 與風險 API 不在本次移除範圍，沒有新增 AI 預測。
- 統一「分享院所頁」與「批次排班」。手機改用「區間清單／當日清單／七日清單」；桌面仍為清單、人員日曆及週行程。
- 服務頁提供「人員服務對應」直接接續既有設定，保留目前院所與示範情境，不新增另一套編輯入口。
